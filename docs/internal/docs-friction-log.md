# Docs friction log

Writing a doc is also a design review. This file collects the design friction that documenting and
building cairn surfaces, so a rough edge becomes a tracked candidate for work instead of a lost
observation. Triage feeds `ROADMAP.md` and `docs/STATUS.md`; this repo keeps no separate backlog file.
A finding here does not block the doc that found it.

Record each finding with its perspective and a short note. The perspective is one of the five
audience profiles ([`2026-08-14-audience-profiles.md`](./record/2026-08-14-audience-profiles.md)): `editor`
(the non-technical author working in `/admin`), `admin` (the technical non-developer who sets up
and runs the default site; `operator` retired into this tag 2026-08-14), `extender` (the
Svelte-fluent developer building on cairn's seams; formerly tagged `developer`), `contributor`
(the engine contributor working on cairn itself; formerly tagged `maintainer`), or `scripter`
(anyone automating against `cairn`, a person writing a script or an agent; the profile the
2026-08-14 record's dated note added for the three tool contract pages under
`docs/reference/`).

Open findings sit in three groups by who clears them (Geoff, 2026-10-08). **Engine** entries feed
the docs-stage boundary test and are cleared by it at each stage close, riding `ROADMAP.md`'s
batched engine friction entry or an engine pass. **Docs content** is any way a page fails its
reader: a wrong claim, a missing working example, step, or failure case, too much or too little
detail for the task, content in the wrong track or page or unfindable from where a reader looks, or
drift since writing. The filing test is whether the reader can finish the page's job from the
page. The pass that meets a small docs item fixes it on the page, except on an arm whose stage is
in flight or a page the running plan freezes, where it is filed here; a larger docs rework moves
to a `ROADMAP.md` row in the tier where it bites.
**Repo tooling** is gates, scripts, fixtures, and tooling comments: a pass that meets a small
tooling item fixes it there, and anything larger moves to a `ROADMAP.md` row in the tier where it
bites.

This log holds only live findings and the tombstones below. Resolved findings are pruned here once
shipped; their detail lives in git, PR bodies, and `docs/STATUS.md`, the homes for shipped
history. The append-only prose that accumulated through 2026-06-26 was pruned on 2026-06-28
(extensibility Plan 1), and the full backlog was cleared on 2026-07-16 by the friction-triage pass:
every open finding was verified against the code and then either shipped, filed into `ROADMAP.md`
with its trigger, or found already resolved and pruned. Git history holds the full record of both
clearings.

## Tombstones (decided, do not resurface)

- **Point-of-typing writing coach.** KILLED 2026-06-26. The help-shell adversarial review discarded it
  as the Clippy pattern. Do not re-propose a per-keystroke formatting coach.
- **`runtime.publicMediaResolver`.** DROPPED 2026-06-24. An adversarial review, verified first-hand,
  found it inverts the prerender/Worker boundary and that the "three wire-points" was a miscount of two,
  both prerender-side and already sharing one `cairn.config` export. The real wart (silently broken
  public images) is fixed instead by the `media.resolver_absent` warn event at `createPublicRoutes`
  construction. Do not re-propose the runtime member.
- **`CairnMediaLibrary`'s dormant "type facet" (a hidden Images/Documents filter).** RESOLVED
  2026-07-20, admin-toolkit review-fixes round. The pass's T8 drift-hunt had filed this as a live
  open finding, attributing the facet's absence to T6's `ListToolbar` re-expression; `git log`/`git
  show` on `CairnMediaLibrary.svelte` instead confirm the facet was removed three weeks earlier, in
  the 2026-06-28 charter-adherence pass (`23abe438`, "the speculative Media Library type-facet is
  removed"), as inert scaffolding for a second stored asset type that has never existed. T6 never
  carried it forward because it was already gone at the branch point. The delivery route is still
  image-only today, so the charter's "we don't accommodate that universe" stands: do not re-add it
  speculatively. `ListToolbarFilter`'s `promoted: false` seam covers the same hidden-until-needed
  shape if a real second asset type ever ships.

## Open findings

New findings start in the group they belong to, one per finding, with its perspective and a short note.

### Engine

- **`extender`.** The root barrel exports `parseMarkdown` but not its inverse `serializeMarkdown`, so a migration script reads frontmatter with cairn's parser and must hand-write the `---` block it writes back. A hand-written block is where the YAML traps bite: an unquoted number, date, or boolean reads as empty in a text-like field, and an unquoted timestamp parses to a `Date`. The migrate-existing-content page has to teach quoting rules a one-line export would make moot. Fix candidate: export `serializeMarkdown` (the `matter.stringify` wrapper) from the root barrel beside `parseMarkdown` (`src/lib/content/frontmatter.ts:387-399`, `src/lib/index.ts:54`; found while writing the migrate-existing-content page, 2026-10-12).
- **`extender`.** A component's `build` reads `ctx.attributes.<key>` and gets `undefined` at runtime for a key the component def never declared, with no type error and no warning, because `attributes` is a plain `Record`. Fix: document that a build may read only declared attributes, or warn in dev when it reads an undeclared key (found by the ecnordic 0.21 migration, 2026-07; verified against `src/lib/render/registry.ts` on 2026-10-11).
- **`extender`.** `DatetimeField` declares `min` and `max` ("Earliest allowed moment as an ISO string") that neither the save validator nor the form enforces, while `DateField`'s same-named options are enforced at save. A developer who sets them gets no bound and no warning. Fix: enforce them at save like `DateField`, or drop them from the type (`src/lib/content/fields.ts:74-81`, `src/lib/content/fieldset.ts:292-306`; found while writing the content-model page, 2026-10-12).
- **`extender`.** Field constraints reach the form unevenly: `NumberField`'s `min`, `max`, and `integer` render as input attributes, but `TextField`/`TextareaField` `min`, `max`, `length`, and `pattern` and `DateField` `min`/`max` do not, so the browser accepts a value the save then refuses with one banner. Fix: render the matching HTML attributes (`maxlength`, `minlength`, `pattern`, a date input's `min`/`max`) on every constrained leaf (`src/lib/admin/FieldInput.svelte:218,227-237,264`; found while writing the content-model page, 2026-10-12).
- **`extender`.** `MultiselectField`'s three options interact in a surprising way: `creatable: true` beside `options` swaps the checkbox group for a free-typing tag input whose out-of-list values the save still rejects, and `placeholder` applies only to that tag input, never the checkbox group. Fix: either make `creatable` widen the closed set or refuse `creatable` with `options` at declaration, and document `placeholder`'s scope on the type (`src/lib/content/frontmatter.ts:16-22`, `src/lib/content/fieldset.ts:207-224`; found while writing the content-model page, 2026-10-12).
- **`contributor`.** The `src/lib/content/manifest.ts:1-5` header still says "the save path patches one entry and commits it with the content in one commit", but a save commits no manifest; publish patches it (`src/lib/sveltekit/content-routes-entry-write.ts:92,358`). Fix the comment in the next engine pass that touches the file (found while writing the content-model page, 2026-10-12).
- **`extender`.** The admin sidebar has four ways to hide a link, none of which authorizes: `hidden` on an engine reference, `ownerOnly` on a site entry, `roles` on a site entry or a section, and `navFilter`. They also cover the node kinds unevenly: an engine reference takes neither `roles` nor `ownerOnly`, so narrowing one engine screen by role means wrapping it in a section, and a section takes `roles` but not `ownerOnly`. A page has to state four cosmetic gates and send the reader elsewhere for the real one. Fix candidates: give the node kinds one gate vocabulary, or derive nav visibility from the access map (`src/lib/sveltekit/admin-nav.ts#NavLayoutEngineRef`; found while writing the arrange-the-admin-sidebar page, 2026-10-12).
- **`extender`.** One feature, three names: the adapter turns the public menu editor on with `editor.nav` (type `NavMenuConfig`), `navLayout` references it as `screen: 'nav'`, and the startup error for a missing `editor.nav` says `navLayout: screen "nav" is referenced but no navMenu is configured`, naming neither the adapter key nor the type. The bare word `nav` also collides with `navLayout` and `navFilter`, which arrange the admin sidebar, not the public menu. Fix: name `editor.nav` in the error message (`src/lib/sveltekit/admin-nav.ts#validateNavLayout.checkEngineRef`; found while writing the arrange-the-admin-sidebar page, 2026-10-12).
- **`extender`.** `buildNewlyPublished` reads a renamed entry, and one deleted and recreated under the same id, as newly published, because it matches on the `concept`/`id` key alone; a site announcing new posts re-announces a rename unless it filters on its own. The page states it as an edge case (`src/lib/delivery/manifest.ts#buildNewlyPublished`; found while writing the act-on-newly-published-entries page, 2026-10-12).
- **`extender`.** A `publishActions` href substitutes `{concept}` and `{id}` verbatim, with no URL encoding, so a developer who places either in a query string must trust the id's character set (`src/lib/sveltekit/publish-actions.ts#resolvePublishActions`; found while writing the act-on-newly-published-entries page, 2026-10-12).

- **`extender`.** A dated entry carries two dates that can disagree. The create action composes the filename's leading date from the `date` field once, `renameId` keeps that prefix, and nothing rewrites it when an editor later changes `date`, so the filename says one day while the entry's date, its dated permalink, and its templates use another. A page has to warn that the filename's date is not the entry's date. Fix candidates: rewrite the prefix through the rename path when `date` changes, or stop putting a date in the filename (`src/lib/sveltekit/content-routes-entry-read.ts:248`, `src/lib/content/ids.ts:65,90-94`; found while writing the content-model page, 2026-10-12).

Fix candidates: preserve the five engine-read keys through a save, or warn at declaration when a concept omits one the delivery layer reads (`src/lib/delivery/content-index.ts#createContentIndex`, `src/lib/content/manifest.ts#manifestEntryFromFile`; found while writing the content-model page, 2026-10-12).
