# Cleanup claims for the evaluation brief

One testable core claim per item of the evaluation brief, written before any trial text
was extracted. Each names the allowed page that supports it.

1. What it is and what it refuses to be: cairn is an editor-first, git-backed CMS for SvelteKit sites on Cloudflare with one fixed concept shape and a site-supplied `render`, and it is not an open-ended collection model (`docs/why-cairn.md` "What cairn offers"; `README.md` "What cairn is").
2. An editor's day: an editor signs in from an emailed link with no password or GitHub account, writes markdown beside a live preview, and publishing copies the entry's per-entry branch to the default branch through the site's GitHub App with the editor as commit author (`docs/why-cairn.md` "What cairn offers"; `docs/architecture.md` "The write path").
3. Ownership and leaving: the content is markdown files in the site's own repository and images in its own R2 bucket, so leaving means cloning the repository and copying the bucket, and blocks, `cairn:` links, and `media:` references need conversion (`docs/why-cairn.md` "Where cairn stands").
4. Cost: cairn is free MIT code, and a site's running cost is the Cloudflare Workers Paid plan at $5 a month plus about $10 to $15 a year for a domain if you connect your own, as of 2026-08-11 (`docs/admin/before-you-start.md` "What it costs").
5. Sign-in and secrets: sign-in uses a 256-bit single-use token valid 10 minutes, stored only as a SHA-256 hash and completed only in the requesting browser, and the GitHub App's private key is a Worker secret that signs a JWT for a short-lived installation token (`docs/architecture.md` "The security model").
6. Extending, tiers, stability: a developer extends through documented seams with custom code, exports carry `@public`, `@beta`, or `@scaffold` tier tags, and the engine is pre-1.0 so a break can ship in a minor release, each listed in the changelog and migration notes (`docs/architecture.md` "Stability tiers"; `docs/why-cairn.md` "Where cairn stands").
7. Claude Code, the eval, no MCP: cairn ships four skills and a review agent in the package, an 18-case eval counted 16 cases with the packaged guidance passing all five trials of 15 and four of five on the other at 74 percent of the tokens and 61 percent of the wall time, and it ships no MCP server because skills on disk also reach agents with a fixed tool list (`docs/architecture.md` "Claude Code guidance").
8. Contribute: a contributor clones the repository, accepts the folder's trust dialog in Claude Code, runs the fast lane, opens an issue first for anything large, and opens a pull request against `main`, where CI is the authority on the gates (`CONTRIBUTING.md` "Working with Claude Code", "Proposing a change", "The gates").
9. Adopt or not: the stated costs are custom code with no plugin market, relational queries left to the developer, one platform vendor, and editors learning markdown, and the right choice depends on whether the organization has a developer and wants its tools in one place (`docs/why-cairn.md` "Trade-offs against other setups").
