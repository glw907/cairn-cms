## Zero-state proof

An empty site needs state no fixture run has, and `fake-github.ts` holds that state at module level
for one Worker. A second `wrangler dev` from the same build keeps the empty site out of every other
spec. The harness adds `content: 'empty'` to `DevBackendConfig`, a var that picks it, and a second
`webServer` entry. Playwright runs the entries in order and each setup waits for its server, so the
build finishes before the second server starts (`createPluginSetupTasks`, `playwright/lib/runner/index.js:6542`).
The config already sets `use.baseURL`, which an array of servers needs: `webServerPluginsForConfig`
otherwise lets the last entry win through `PLAYWRIGHT_TEST_BASE_URL`.

The new tests stay inside `admin-visual.spec.ts`. `e2e.yml:163` regenerates baselines by naming that
file and `site-visual.spec.ts`, so a new spec file would need a `runner` workflow edit.

The proof covers five screens, in light, at 320 and 2560: posts office, tags, navigation, media, and
help. That is ten images. Editors always holds the owner row, history's `EmptyState` needs a degraded
GitHub read, and site settings has no empty form, so none of those has a zero state to prove. The
office screens for pages and fragments share posts' branch of `ConceptList`, and pickers are controls
inside a screen. Light alone is enough: the dark theme changes tokens, never composition, and T12
renders nav, tags, and help in dark on the empty port, six uncommitted images read by eye.

`EmptyState` keeps its `min-h-[56vh]` and gains no prop, since the Brief rules out new surface. On
navigation and tags, the Save control hides while the working copy is empty and nothing is saved,
because a Save under an empty fill offers nothing. It stays when the last row was just removed, so
that removal can be saved.

## Sign-in touchpoints

The Brief makes one design call here, on the email. The login and confirm pages read as composed in
the probe, and no ruling asks for a redesign, so they change only in wording.

**One wording (#182, with #176 merged in).** A refusal with no cookie can't tell a spent link from a
second browser (`auth-routes.ts:344-349`), and a refusal with a cookie can't tell a spent link from
an expired one. One sentence therefore states the rule and the fix, and both `?error` codes show it:

> That sign-in link didn’t work. A link works once, for 10 minutes, in the browser that requested it. Request a new link below and open it in this browser.

It lives in one new internal module, `src/lib/admin/sign-in-copy.ts`. The confirm page's `no-pending`
branch and `refusal-codes.ts`'s `expired` code go, because the engine only ever redirects both to
`/admin/login` (`auth-routes.ts:330,353,355`), so each needs a crafted URL. Both redirect codes stay,
since integration tests and the logs read them, and `PENDING_COOKIE_TTL_MULTIPLE` keeps its value,
since a shorter cookie is a behavior change this pass doesn't need.

**The email.** One restrained layout, per the Brief: the site's name as text, one button, the link
written out, the expiry, the ignore line, and a matching plain-text part. There are no images, remote
assets, or tracking. The button is a single-cell `role="presentation"` table holding an anchor, the
form Postmark's own transactional templates use, with the styles inline since a `<style>` block is
not safe across clients and the colors fixed so a client's dark mode has less to invert. The link is
written out below the button, as Postmark's password-reset template does. `link` is escaped in the
attribute and the visible text alongside `siteName`.

**#255.** `cloudflareSend` keeps the binding's result (`send(...): Promise<EmailSendResult>`, with
`messageId: string`, Cloudflare Workers API docs and `workers-types/index.d.ts:15107`) and logs a new
`auth.link.sent` record with `email` and `messageId`. `auth.token.minted` can't carry it: it logs
before the send. This leaves `SendMagicLink` and `auth-routes.ts` alone, against the item's wording,
because a custom sender owns its own logging and the smaller change adds no public surface. The
docs say so, so an owner with a custom sender doesn't read a missing record as a failed send. The
event name does join the `/log` surface, so T3 regenerates `api-surface.md`.

## Refused forms

**`use:enhance`, the one mechanism.** `EditPage` already uses it, and the payload-echo alternative
needs a shape per failure type. On a failure, Kit leaves the component and its `$state` alone, so the
working copy survives with no echo. On a bare URL it applies `form` in place. From a URL with a query,
such as `/admin/nav?saved=1`, the result's `location` differs from the current URL, so `update()`
navigates (`app/forms/client.js:89-109`): the load reruns, the query clears, and a stale success
banner goes with it, which is the right outcome. Neither path unmounts the screen, and the refusal
tests cover both.

Five things shape the shared code, one internal module `src/lib/admin/refusal.ts`:

1. **Success stays a full document load where it is one today.** Navigation, tags, and tidy announce
   a save by filling a status region after mount (`NavTree.svelte:34-41`, the #215 fix). Under Kit's
   default `goto`, a second save goes from `?saved=1` to `?saved=1`, the text doesn't change, and
   nothing is voiced. The shared submit function therefore answers a `redirect` result with
   `location.assign`, which keeps those three screens' success paths as they are today. ManageEditors'
   actions return `{ ok: true }`, never a redirect, so its table refreshes in place and a `role="status"`
   line says so.
2. **An `error` result leaves the screen alone.** `update()` would pass it to `applyAction`, which
   renders the error page and unmounts the working copy, on a stale CSRF token, a network failure, or
   a thrown 403. `EditPage` already refuses that for the same reason (`EditPage.svelte:250-253`). The
   function calls `update()` for `success` and `failure` only, and the screen shows `EditPage`'s notice.
3. **One POST at a time.** A save is a GitHub commit, seconds long, and `use:enhance` shows nothing and
   guards nothing. Each form's function holds a pending flag, cancels a repeat, and its button shows
   the flag.
4. **Focus moves to the alert when it mounts.** `applyAction` sets `props.form = null`, awaits a
   tick, then sets the result (`kit/src/runtime/client/client.js:2980`), so an `{#if}` alert remounts
   on every refusal, an identical repeat included, and a mount-time action fires each time. It only
   calls `reset_focus` on `success`, so nothing takes the focus back. The same action runs on
   hydration, so a post made before hydration gets the move too. A true no-JS post doesn't, since
   nothing hydrates. GOV.UK's error summary is the published pattern: "move keyboard focus to the error
   summary".
5. **The polite region and its nonce go.** A focus move speaks the alert, and the polite region would
   then say it a second time. Removing it deletes the hand-rolled idiom from these five screens.
   `standards:daisyui-a11y-reviewer` reads this at close.

`ConceptList`'s create dialog needs one more step: a modal makes the page behind it inert, so the
list's banner can't reach the editor. A refused create renders its alert inside the dialog, which
stays open with Title, Slug, and Date as typed, and clears `creating`.

**The conflict message changes.** Today a conflict refusal reseeds the page, so "Reload and reapply
your edits" is true. Once the working copy stays, a second Save reads the new head and passes the
guard, so it replaces the other editor's change. A stale tab can already do this, so T6 adds no new
class of overwrite, but the screen now offers it just after naming the conflict. The sentence says so
plainly, and a load-time head goes to the backlog as its own item.

## #238

**Server half.** `ContentFormFailure` gains `field?: string`, set from the first key of
`result.errors`. `EditPage` finds the control by name, reveals it the way `onFormInvalid` does,
sets `aria-invalid`, and focuses it, clearing the attribute on the next input. A field with no single
visible control falls back to the banner, which takes the same focus action. The existing assertive
region stays, since `EditPage` is outside the cluster.

**Paste and trim.** No ruling exists. The recommended reading, stop S1 in the plan, is warn: drop
`maxlength` and `minlength` from the three inputs that set them, and report the trimmed length through
`setCustomValidity` using `stringLengthError`, the server's own rule, skipping an empty value, which
`required` owns. Nothing the editor pasted is ever cut, both sides count the same string once a field
is edited, and the `validator` mark `admin-rest` added keeps reporting length.

## #256

Thrown text reaches logs and never an editor (`cairn-admin.ts:233`), so the reader is the site owner.
Each string keeps its operation and status and gains the next step. GitHub strings share one
constant, worded conditionally and placed before the raw response body, and the 422 at
`branches.ts:54` gets its own text. `defineRoles` strings each name their fix. The
item's 13 are `branches.ts:33,54,56,67,92` and `repo.ts:65,85,138,175,184,226,235,246`. The two
`signing.ts` DER strings, `repo.ts:67`, and `repo.ts:291` sit outside that count and stay: three are
programmer invariants, and `repo.ts:67` already says what went wrong.

## Keyboard walk

A scripted spec drives Tab and Enter through sign-in, edit-and-save, and publish on the dev backend.
It asserts the focus order and that each result is reachable, then records what it found. The dev
backend mints the owner session, so the sign-in leg proves the login and confirm forms by keyboard,
not a full round trip; the live smoke at close carries the round trip. Orca goes to the backlog for
the site work, per the Brief.

## Risk

`ordinary`, `auth-data` by item. `src/lib/github/**`, `src/lib/auth/roles.ts`, and
`examples/showcase/src/hooks.server.ts` are on the map; `auth-routes.ts` and `auth-error-codes.ts` are
touched in comments only. The security read and live smoke stay on either way, per the launch prompt.
`email.ts` is off the map and takes a failing test first regardless.

## Contestable points

Each is reversible, and the conductor can overrule any of them before launch.

- Full document load on success, in place of Kit's `goto`. It trades a smoother save for exact
  parity with today's announcements.
- #276 comes in as a scroll cue, 15 minutes on the path, because "composed at 320 and 2560" is a
  May-not. Leaving it out records four 320 baselines of a clipped filter, needs an explicit exception to
  the May-not, and is never a default.
- #248 leaves Pass 7 for the Cleanup round: the sheet never scoped it, and it needs a new option, a new
  outcome arm, and a decision on the `throttled` oracle. Bringing it in means building all three.
- Ten zero-state images in light only. Dark would add 10 committed images; the plan takes 6 uncommitted
  ones read by eye.
