**One correction against the plan's pre-written table.** `AdvisoryAction`'s literal expression
`EditData['advisories'][number]['actions'][number]` does not compile: `AdvisoryNotice.actions` is
optional (`actions?: AdvisoryAction[]`), so indexing the plain union with `[number]` fails
(`TS2537`, verified directly against `src/tests/unit/retires-task2-sanctioned-leak-replacements.test.ts`,
which failed exactly this way before the fix). The compiling form wraps the optional member in
`NonNullable` before indexing: `NonNullable<EditData['advisories'][number]['actions']>[number]`,
used above and in the fixture.

## The standing leak arithmetic

**Predicate:** a retire-verdicted name, absent from every subpath's export list in
`docs/internal/api-surface.md`, named inside a surviving rendered public shape.

**Expected count after this task: 20.** The 18 sanctioned leaks above, plus two names this task

`TidyFailure`, both arms of `createCairnAdmin`'s `dictionaryAdd`/`tidy` actions

`- \`TidyFailure\`:` declaration rows.

**One rendering caveat for a mechanical derivation over the snapshot text.** `AdvisoryAction`
appears NOWHERE in the regenerated `docs/internal/api-surface.md`, not even inside a keep parent's
shape (`grep -c AdvisoryAction docs/internal/api-surface.md` is 0): `check-surface.mjs`'s renderer
expands a named type one hop from its own top-level entry, and `AdvisoryAction`'s only carrier,
`AdvisoryNotice`, lost its own top-level row this task (case 3, still exported, but no longer
published from any subpath), so nothing in the rendered file reaches a second hop into
`AdvisoryNotice.actions`. A script deriving the leak set by grepping this file directly therefore
finds 17 named leaks among the 18, not 18; `AdvisoryAction` is real and reachable in the actual
TypeScript type graph regardless (`EditData['advisories'][number]['actions']` still resolves it,
proven by the compile-only fixture), so this is a known rendering-depth limit of the snapshot text,
not a missing leak. The internals pass's permanent rider should derive the leak set against the
TypeScript checker's own type graph (as this task's fixture does), not against the rendered
markdown, to avoid re-discovering this gap as a false 17-vs-18 discrepancy.

**Two written exclusions, out of the predicate's reach:**

- `RemoveIndex`, `ValueOf`, and `StandardResult` are never-exported internal type helpers that sit
  outside the `check-surface.mjs` export model entirely (they support the `Fieldset` standard
  schema machinery but are never themselves subpath exports and never retire-verdicted), so the
  predicate's first clause ("a retire-verdicted name") never reaches them.
- `NavIcon`, `EngineScreenId`, and `SlotKind` (R4 re-derivation, section 1) are the EXPANSION
  class, not the leak class this predicate scopes to: each is rendered EXPANDED (the full literal
  union inlined at every reference site), never referenced BY NAME, in the shapes that would
  otherwise carry it (`NavLayoutEntry`, `NavLayoutEngineRef`, `SlotDef`). The predicate's third
  clause ("named inside a surviving rendered public shape") does not match an expansion, so these
  three sit outside it. Distinct from the leak class this task's 18 join, where the renderer DOES
  print the retired name verbatim (confirmed directly: `NavConcept` still renders by name inside
  both `AdminShellData` and `ReproStory`, `ReproInstance` still renders by name inside `ReproStory`,
  after this task's own `check:surface -- --update`).
