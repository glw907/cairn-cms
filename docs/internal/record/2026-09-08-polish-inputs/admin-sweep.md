## Findings (ranked by user cost)

**1. Blocker — `Ctrl/Cmd+B` and `Ctrl/Cmd+K` fire the shell's global handler *and* the editor's, every keystroke.** `/var/home/glw907/Projects/cairn-cms/src/lib/components/CairnAdminShell.svelte:254-262` binds both chords on `<svelte:window onkeydown>` with no `e.target` / `e.defaultPrevented` guard. `/var/home/glw907/Projects/cairn-cms/src/lib/components/EditPage.svelte:1276-1294` (`onEditorKeydown`, attached to the editor card at 1272) calls `e.preventDefault()` but never `stopPropagation()`, so the event bubbles to the window. Result while writing: **Ctrl+B bolds the selection and toggles the nav drawer**; **Ctrl+K opens the Web link dialog and stacks the command palette on top of it**. Below `xl` on a desk route the drawer toggle also flips `isDrawerOverlay`, which moves focus into the nav and `inert`s the manuscript (`CairnAdminShell.svelte:497-503`, `:606`) — a bold keystroke yanks focus out of the document. `editor-shortcuts.ts:27` and `:35` even document `Ctrl K` twice, as "Web link" and "Command palette (global)". WCAG 2.1.1 / 3.2.2 / 2.4.3. **Mechanic.** Fix: have `onEditorKeydown` call `e.stopPropagation()` on every chord it consumes, and gate the shell handler on `e.defaultPrevented` plus a non-editable target.

**2. Blocker — the drawer/hamburger toggle has no keyboard tab stop and no accessible name.** `CairnAdminShell.svelte:635` is `<label for="cairn-shell-drawer" aria-label="Open menu" class="btn btn-square btn-ghost">`. Labels are not focusable, and its target checkbox at `:593-601` carries `tabindex="-1"` and `aria-hidden="true"`. So below each route's persist breakpoint (every phone and tablet width, and 1024-1279px on a desk route) the sidebar's only pointer trigger is unreachable by Tab, gets no focus ring, and exposes no button role or name to AT. The only keyboard path is the undocumented Cmd/Ctrl+B, which finding 1 shows is itself broken. Same shape at `:814` for "Close menu". WCAG 2.1.1, 4.1.2, 2.4.7. **Mechanic.** Fix: render a real `<button type="button" aria-expanded={drawerOpen} aria-controls="…">` that flips `drawerOpen`, and keep the checkbox purely as the CSS mechanism.

**3. Blocker — the shared pressed-state hairline is a 20% mix the repo already condemned twice, and it is the *sole* cue on an icon-only control.** `/var/home/glw907/Projects/cairn-cms/src/lib/components/segmented-control.ts:16-20` returns `ring-1 ring-inset ring-base-content/20` and its doc comment claims it as "a non-color, non-weight pressed cue (WCAG 1.4.11 non-text contrast)". A 20% `base-content` mix is exactly the value `cairn-admin.css` rules 12 and 13 measured at **1.492:1 light / 1.773:1 dark** and raised to 55% for the checkbox, radio, input, select and textarea edges (`admin-design-system.md:222-238`). The tint beside it, `bg-base-content/[0.07]`, is fainter still. Every other caller (`CairnTidySettings.svelte:329,334`, `TidyReview.svelte:277`) also renders a check glyph, so the ring is decorative there — but `CairnMediaLibrary.svelte:608-609,690-695`, the Grid/List density toggle, is **icon-only with no glyph**, so its selected state is conveyed at roughly 1.4:1 to a sighted user. WCAG 1.4.11. **Mechanic.** Fix: raise `segmentTintClass`'s ring to the already-locked `color-mix(… base-content 55% …)` and re-measure the tinted band, or give the density pair a check glyph like every other caller.

**4. Warning — command palette is not a combobox (confirms the filed item, and it is worse than filed).** `CairnAdminShell.svelte:721-732` is a bare `<input aria-label>`; the results at `:744-773` are a `<ul role="list">` of links. Missing: `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, ArrowUp/ArrowDown traversal, and roving tabindex — Enter blindly clicks the first DOM result (`submitPalette`, `:412-414`) regardless of what is focused. No `aria-live` count and no live "No matches" (`:775` is a plain `<p>`), so a filter that narrows to zero is silent. This is the same surface `MediaPicker` implements as a full ARIA 1.2 combobox with two live regions (`admin-design-system.md:802-808`), so the palette is the family's one defector. WCAG 4.1.2, 2.1.1, 4.1.3. **Mechanic.**

**5. Warning — `aria-disabled` for busy in `ShareLinkPanel` contradicts a ruling already written down (confirms the filed item).** `/var/home/glw907/Projects/cairn-cms/src/lib/components/ShareLinkPanel.svelte:184` and `:193`. `EditPage.svelte:1576-1578` states the rule in prose: *"Native disabled is reserved for busy (mid-submit), the one case the guidance sanctions."* `admin-design-system.md:548-551` says the same. ShareLinkPanel is the only component that uses `aria-disabled` for an async round trip. It also drags `cairn-btn-guarded` along, whose entire purpose is restoring `pointer-events` so a `title` tooltip survives (`admin-design-system.md:843-849`) — these two buttons carry no `title`, so the marker is cargo-culted onto a control with no tooltip to preserve. Fix: `disabled={shareBusy}` / `disabled={revokeBusy}` and drop `cairn-btn-guarded` and `class:cursor-not-allowed`. **Mechanic.**

**6. Warning — WCAG 2.4.11 is solved for the sticky topbar and left open for the fixed bottom bar.** `cairn-admin.css:631-633` gives every focusable `scroll-margin-top: 5.5rem` explicitly for Focus Not Obscured. `EditPage.svelte:2303-2306` renders a `fixed inset-x-0 bottom-0 z-40` action bar (~60px) on every desk route below `sm`, and there is no `scroll-margin-bottom` anywhere in the tree (grep: the 5.5rem rule is the only scroll-margin in `src/lib`). A control tabbed to near the bottom of the manuscript or the footer strip scrolls flush to the viewport bottom, under the bar. WCAG 2.4.11 (AA, 2.2). **Mechanic.** Fix: add a matching `scroll-margin-bottom` to the same rule, or scope one to the desk route.

**7. Warning — five `role="status"` regions are mounted with their first content, which the repo's own rule forbids.** `MediaUploadDialog.svelte:264`, `MediaHeroField.svelte:496`, `MediaReplaceDialog.svelte:421`, `CairnTidySettings.svelte:347`, `NavTree.svelte:134`. `EditPage.svelte:1751-1754` and `ShareLinkPanel.svelte:214-217` both carry the correct always-mounted recipe and cite WCAG 4.1.3 for it. The upload/replace/hero cases are the ones that bite: an upload beginning is exactly the moment an editor needs the announcement. WCAG 4.1.3. **Mechanic.** Fix: hoist the region out of the `{#if}` and gate only its contents.

**8. Warning — the same three publish states render in two different chip vocabularies.** `EditPage.svelte:836-840` maps Edited→`badge-warning`, New→`badge-info`, Published→`cairn-chip-quiet`, applied raw at `:1413` and `:1423`. `ConceptList.svelte:428-430` renders the identical three states as `StatusChip` `quiet` for all three, and its own comment (`:423-427`) cites the ratified reason: *"the label text itself as the distinguishing signal."* `badge-warning` and `badge-info` are also outside the blessed badge tier (`admin-design-system.md:424-441`: `badge-error`, `badge-success`, `badge-soft`, `badge-outline`, `badge-dash`), as is `badge-neutral` at `EditPage.svelte:1425`. This is also a direct hit on the charter's standing grade "too many popping colors on one screen". **Mechanic.** Fix: route the desk band's pill through `StatusChip`, or record the desk exception in the badge-tier ruling with its measurements.

**9. Warning — the starter template teaches placeholder-as-label.** `/var/home/glw907/Projects/cairn-cms/examples/showcase/src/routes/admin/signups/+page.svelte:17-20`: `<label class="sr-only">` plus `placeholder="Name"` / `placeholder="Email"`. Programmatically labelled, so 1.3.1 passes, but a sighted user sees only a placeholder that vanishes on the first keystroke, and none of the three ratified form-row registers (`admin-design-system.md:263-284`) is an `sr-only` label. This file is the exemplar a scaffolded site copies. WCAG 3.3.2. **Design choice in the template, but it propagates as a mechanic.** Fix: use the stacked register (`type-body font-medium` label above the control), the way `LoginPage.svelte:145-146` does.

**10. Warning — three identical "Delete" buttons in the signups table, no distinguishing name.** `examples/showcase/src/routes/admin/signups/+page.svelte:39`. The engine's own equivalent does it right: `ManageEditors.svelte:147` uses `aria-label={`Remove ${editor.displayName}`}`. WCAG 2.4.6, 4.1.2. **Design choice.** Fix: `aria-label={`Delete ${s.name}`}`.

**11. Warning — the signups Delete is a one-click destructive submit with no confirmation.** Same line as above. Every destructive path in the engine goes through a `DeleteDialog` / safe-delete `alertdialog` (`admin-design-system.md:917-923`), so the exemplar teaches the opposite of the engine's own recipe. **Design choice** (but the exemplar is the contract a developer reads). Fix: route it through `DeleteDialog`, or at minimum a confirm.

**12. Warning — the signups create form cannot compose at 320/390.** `examples/showcase/src/routes/admin/signups/+page.svelte:15` is `class="my-4 flex gap-2"` holding two `.input`s and a `.btn`, with no `flex-wrap`, no `min-w-0`, and no `sm:` breakpoint. The family five-viewport bar (`admin-design-system.md:28-29`, 45-49) requires composition at 320, and the charter calls responsive craft something a developer must inherit from the exemplar. **Unverified by render** — I could not build. Fix: `flex-col gap-2 sm:flex-row` with `min-w-0` on the inputs.

**13. Warning — the signups screen has no live region for either action's outcome.** Both `?/create` and `?/remove` return with no `role="status"` and no error surface, so adding or deleting a row announces nothing and a failure is silent. WCAG 4.1.3, 3.3.1. **Design choice.**

**14. Warning — the palette trigger omits `aria-haspopup="dialog"`.** `CairnAdminShell.svelte:676-690` opens a modal `<dialog>` and carries no `aria-haspopup`, while its sibling Publish-site trigger at `:700` does, and `admin-design-system.md:984-989` states the rule explicitly ("a trigger that opens a modal `<dialog>` carries `aria-haspopup="dialog"`"). WCAG 4.1.2. **Mechanic.**

**15. Warning — the desk band's Save/Publish pair flashes the wrong composition on every phone load.** `EditPage.svelte:869-878`: `narrow` defaults `false` and is corrected in an `$effect` after mount, so SSR ships the wide `{#if !narrow}` branch (`:1567`) with Save and Publish inline in a 48px band. On a phone the first paint is the desktop composition, then it swaps to the fixed bottom bar. `admin-design-system.md:148-150` sets the opposite standard for the sidebar recede ("resolved at SSR so the chrome state never flashes"). **Mechanic.** Fix: seed `narrow` from a server-read hint the way `data.theme` and `data.collapsedNav` are, or render both branches with CSS `hidden` and disambiguate by `aria-hidden` + `inert` rather than by DOM presence.

**16. Warning — the hero dropzone uses the Tailwind v3 utility name and a 1px focus ring.** `MediaHeroField.svelte:450` writes `focus-visible:outline-none`. In Tailwind 4 `outline-none` means `outline-style: none`; the v3 spelling is now `outline-hidden`. Every other call site in the tree already uses `outline-hidden` (`MediaPicker.svelte:195`, `CairnMediaLibrary.svelte:747`, `ComponentInsertDialog.svelte:420`). It also replaces the admin's 2px brand `:focus-visible` ring (`cairn-admin.css:566-569`) with `focus-visible:ring-1` at a 70% primary mix — half the width of every other control, on the only focusable element in an otherwise empty field. WCAG 2.4.7. **Mechanic.** Fix: `outline-hidden` and `ring-2`, or drop the override entirely and let the sheet's ring apply.

**17. Warning — `LoginPage` reaches a fill tone through the bracketed-var form the design system bans.** `LoginPage.svelte:78` writes `text-[var(--color-success)]`, and `:79` sets an inline `style="background-color: color-mix(…); box-shadow: inset …"`. `admin-design-system.md:213-215` and `:218-221` forbid the bracket form and name `cairn-text-success` / `--color-positive-ink` as the on-surface counterpart; `:1230-1234` says `check:custom-surface` is supposed to fail exactly this. An inline `style` attribute bypasses that gate entirely. **Mechanic.**

**18. Warning — the "Use a different email" control is color-only at rest.** `LoginPage.svelte:97-103`: `text-primary hover:underline`, no underline until hover. The ratified recipe for a reference-link button is *borderless underlined* (`admin-design-system.md:574-576`). This is the sign-in page's one escape hatch, on the surface a first-time editor meets. WCAG 1.4.1 (borderline: it is not inside a block of text). **Design choice.** Fix: `underline underline-offset-2`.

**19. Warning — `role="status"` wrapping an `<h1>` and a button.** `LoginPage.svelte:79-104`. A live region containing a heading and an interactive control is announced as one blob on any later mutation, and the region is conditionally mounted anyway (`:76`), so it never fires. The component's own comment at `:110-113` concedes the title is what actually announces. Fix: drop the role, or move it to a small text-only region. **Mechanic.**

**20. Suggestion — redundant `aria-label` overriding a real visible label.** `LoginPage.svelte:150`: the input already sits inside `<label>` with a visible `<span>Email</span>` (`:145-146`), and `aria-label="Email"` overrides it. If the visible wording ever diverges, the accessible name silently stops matching. WCAG 2.5.3 risk. Fix: delete the `aria-label`.

**21. Suggestion — decorative icons inconsistently marked `aria-hidden`.** Roughly 25 Lucide glyphs render bare while their siblings are marked: `MediaOrphanTools.svelte:239,259,293,337,398,495`, `MediaUploadDialog.svelte:240`, `MediaBulkDeleteDialog.svelte:294,368`, `MediaAltFillDialog.svelte:197,234,291,350`, `MediaReplaceDialog.svelte:365`, `CairnMediaLibrary.svelte:634,661,691,694,1170`, `LoginPage.svelte:85,92`, `CairnAdminShell.svelte:636,705,952`, `ConceptList.svelte:297,360`. `CairnLogo.svelte:21` sets its own, so those hits are false positives. Most are inside a named button so the name is safe; the exposed ones are the standalone dialog-header and inset-note glyphs. WCAG 1.1.1. **Mechanic.** Fix: `aria-hidden="true"` on all of them, or a lint rule.

**22. Suggestion — `ConceptList`'s sortable column headers omit `scope="col"`.** `ConceptList.svelte:370`, `:381`, `:394`, `:395`. The showcase exemplar writes `scope="col"` (`signups/+page.svelte:26-28`) and `admin-design-system.md:1015` specifies it for the help-page table. Browsers infer scope for a simple table, so this is advisory. WCAG 1.3.1.

**23. Suggestion — confirming the known Pagination gap.** `admin-toolkit/Pagination.svelte:104-112`: the selected page conveys state through `aria-current="page"` and `btn-active` fill alone, with no check glyph. `admin-design-system.md:591-594` already logs this as out of conformance on light and filed to ROADMAP "Next". Still live in the tree. WCAG 1.4.1.

**24. Suggestion — palette results keyed by index across a filtered list.** `CairnAdminShell.svelte:746` uses `(i)`. As the query narrows, Svelte reuses the DOM node at each index, so a focused result silently becomes a different command under the user's cursor. Fix: key on `cmd.label`.

**25. Suggestion — the palette dialog and its search input share one accessible name.** `CairnAdminShell.svelte:717` `aria-label="Search or jump to"` on the `<dialog>`, `:724` the same string on the input, `:726` the same again as the placeholder. A screen reader announces "Search or jump to, dialog. Search or jump to, edit." Fix: name the dialog "Commands" and keep the input's own label.

**26. Suggestion — Copy is a silent no-op when the Clipboard API is absent.** `ShareLinkPanel.svelte:129`: `navigator.clipboard?.writeText(url).then(ok, fail)` short-circuits the whole chain when `clipboard` is undefined, so neither the success path nor the documented select-the-field fallback runs and no message appears. The comment at `:124-126` claims the fallback covers "denied *or* unavailable"; it covers only denied. Low real-world reach (secure contexts only), but the copy affordance is the panel's whole point. Fix: `if (!navigator.clipboard) { shareUrlInput?.select(); return; }`.

**27. Suggestion — `cairn-btn-guarded` applied with no tooltip to preserve.** `ShareLinkPanel.svelte:183` and `:192`. Folded into finding 5; noted separately because `check:custom-surface` pins that class by exact selector and the marker's documented purpose (`admin-design-system.md:843-849`) does not apply here.

**28. Suggestion — the shell injects a global `body` style into the host document.** `CairnAdminShell.svelte:553` `{@html '<style>body { margin: 0; }</style>'}`. The surrounding comment claims it is "scoped to the admin's mount lifetime", but a `<style>` in `<svelte:head>` styles the whole document, and the file's own governing rule is that the admin never touches the host's elements (`admin-design-system.md:108-111`). Fix: zero the margin on the admin root's own containing block instead, or accept and re-word the comment.

**29. Suggestion — the design system names a component that does not exist.** `admin-design-system.md:531-535` says the command palette is "Built in `AdminLayout.svelte`", and `:128`, `:145-151`, `:565-566` all refer to `AdminLayout`. The file is `src/lib/components/CairnAdminShell.svelte`; no `AdminLayout.svelte` exists anywhere in the tree. An agent following the doc will look in the wrong place.

**30. Suggestion — the reduced-motion escape hatch does not cover the theme root itself.** `cairn-admin.css:1111-1119` matches `[data-theme='cairn-admin'] *` (descendants only). Harmless today because `data-theme` sits on a bare wrapper by rule, but the rule and the bare-wrapper rule are enforced in different places. Fix: `[data-theme='cairn-admin'], [data-theme='cairn-admin'] *`.

## Busy-idiom count

Counting only controls that reflect an **in-flight async operation** (not guarded/unavailable states, which are settled as `aria-disabled` + `cairn-btn-guarded`):

| Component | Idiom | Sites |
|---|---|---|
| `EditPage.svelte` | **native `disabled`** | 6 — `:1463` (sr-only default submit), `:1590` (Publish, `disabled={busy}`), `:1597` (Save), `:1935` (tidy), `:2318` (Publish, bottom bar), `:2323` (Save, bottom bar) |
| `ConceptList.svelte` | **native `disabled`** | 1 — `:509` `disabled={creating}` |
| `MediaOrphanTools.svelte` | **native `disabled`** | 1 — `:386` `disabled={… \|\| orphanPurgeBusy}` |
| `ShareLinkPanel.svelte` | **`aria-disabled`** | 2 — `:184`, `:193` |

**Native `disabled`: 3 components / 8 sites. `aria-disabled`: 1 component / 2 sites.**

A third idiom is also in play and worth putting in front of the ruling: **state replacement**, where the busy state swaps the control out for a `role="status"` panel so there is nothing to disable — `MediaUploadDialog.svelte:263-267`, `MediaHeroField.svelte:495-500`, `MediaReplaceDialog.svelte:421`, `MediaCaptureCard` (per `admin-design-system.md:810-815`, "Its submit is never disabled"). That is 4 more components. So the family is 3-to-1-to-4, and the majority idiom for a *button that stays on screen while busy* is native `disabled`, with `EditPage` carrying the written rationale.

Separately, `aria-disabled` for the **guarded/unavailable** state (not busy) is settled and consistent: `EditPage.svelte:1587,1870,1959,2315`, `VocabularyAdmin.svelte:297`, `EntryPicker.svelte:150`.

## Checked and clean

- No Tailwind v3 carryovers apart from finding 16: no `@tailwind` directives, no `bg-opacity-*`, no `flex-shrink-*`/`flex-grow-*`, no bare `shadow`. `shadow-sm` at `CairnAdminShell.svelte:830` and `CairnMediaLibrary.svelte:756` is the documented brand-tile recipe, not a v3 name. `rounded-sm` in `CairnTidySettings`/`TidyReview` is valid v4.
- No DaisyUI v4 survivals: zero hits for `btn-group`, `input-group`, `form-control`, `card-compact`, `btm-nav`, or the `--p`/`--b1`/`--n`/`--er` variable family. `@plugin`-in-CSS configuration throughout; no `require('daisyui')`.
- Zero hardcoded colors in the admin tree: no `bg-[#…]`, no `text-gray-*`, no `blue-500`, no `bg-white`/`bg-black`.
- `data-theme` on a bare wrapper is honored at both mount points (`CairnAdminShell.svelte:562`, `LoginPage.svelte:71`), with the load-bearing reason recorded inline.
- Cascade layering is disciplined: one `@layer base`, one `@layer components`, and thirteen unlayered rules each individually numbered, justified, and pinned by `check:custom-surface`.
- `prefers-reduced-motion` is handled globally at `cairn-admin.css:1111-1119`, which is why the eight ungated `transition-*` utilities in components are not findings.
- Live-region discipline is right where it matters most: `EditPage.svelte:1630-1631` (paired polite/assertive announcers), `:1758` (always-mounted needs-alt/blast-radius `role="status"`), `ShareLinkPanel.svelte:214,238,241`, `CairnMediaLibrary.svelte:943`, `RepeatableField.svelte:312`.
- Drawer modal contract is complete and correctly conditional on `isDrawerOverlay`: `role="dialog"` + `aria-modal`, background `inert`, capture-phase Escape, a real Tab trap, focus-in and focus-restore (`CairnAdminShell.svelte:497-545`, `:606`, `:816-819`).
- Details slide-over follows its own recipe exactly: `role="region"` + `aria-label`, `hidden` for tree/tab-order removal, `flushSync` before focusing the close button, focus return to the trigger (`EditPage.svelte:880-900`, `:2197-2211`).
- Heading structure is sound: `PageHeader` supplies the single `h1` on every office screen; `EditPage.svelte:1785` provides an `sr-only` `h1` because the visible title is an input; no level skips found.
- Semantic elements throughout — no `<div onclick>` anywhere in `src/lib/components` or `src/lib/admin-toolkit`; sort controls are real `<button>`s inside `<th aria-sort>`.
- Popover menus follow the ratified Popover-API recipe with mirrored `aria-expanded`, not the focus-driven `.dropdown` (`EditPage.svelte:1487-1517`).
- `--color-muted` (48%/72%) and `--color-subtle` (42%/80%) clear AA against their surfaces on both themes by inspection; every status color pair (`info`/`success`/`warning`/`error`/`neutral` + `-content`) is defined on both roots, so no badge resolves to an undefined variable.
- 44px touch targets are deliberate where the band is tight (`min-h-11 min-w-11` on the desk band's quiet pair and the narrow-width action bar); `btn-xs` controls land at 24px, meeting 2.5.8 exactly.
- WCAG 2.4.11 top-side coverage is explicit and correctly reasoned (`cairn-admin.css:628-633`).
- Route titles are unique per route via `<svelte:head><title>{pageTitle} · {siteName}</title>` derived from the breadcrumb (`CairnAdminShell.svelte:546`, `:452`).

## Pages rendered

**None.** No showcase build or preview was run, for the contention reason at the top; nothing was started on port 4174 and nothing needs killing. Findings 3, 12, and 16 in particular are geometry and contrast claims derived from token arithmetic and source, and each names the render that would settle it — 320/390/1440 in both themes on `/admin/posts`, `/admin/posts/<id>`, `/admin/media`, `/admin/signups`, and `/admin/login`.
