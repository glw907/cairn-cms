**7. Decision 5 (:45) / Polish-A:138-140 derives the dev access map from the wrong source.**
The spec: *"the dev package's handle attaches `locals.cairnAccess` **resolved from the dev owner session**."* An access map is not a property of a session; it is the site's declaration, passed to `createAuthGuard({ access })`. In dev the guard does not run at all: `examples/showcase/src/hooks.server.ts:18-32` chooses `devBackendHandle()` *or* `createAuthGuard()`, never both, which is why the gap exists. Synthesizing a map from the session copies a fact with one source, against the ratified `read-from-the-source-rule` (:38-48: *"a fact with one source is read from that source, never copied"*), and in an authorization harness the copy's failure mode is dev admitting what production refuses. On the charter question the seam itself is clean: the dev package is cairn's own harness, parity with the guard it stands in for is the engine's job, not the developer's. **Correction: amend :139 so `devBackendHandle` takes the same `access` (and roles) the site hands `createAuthGuard`, attaching it verbatim, with the showcase passing one shared declaration to both branches.**
