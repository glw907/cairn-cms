**5. Spec 159-161 and 219-220 — both passes claim to triage the friction log whole and both write CHANGELOG/ROADMAP/HISTORY/STATUS.** The internals plan chose `parallel: false` for exactly this reason ("shared CHANGELOG, ledger, and check-script files"), and chassis-A's post-mortem records a fix round on "a friction-log rewrite that had dropped `main`'s newer entries." This is a repeat of a known defect. The spec also says the log has "one open entry, owned by the identity seam" (line 13), which contradicts two tasks triaging it. **Correction:** give the friction-log triage and the ROADMAP edit to exactly one pass (B, since it is the docs pass), and constrain the other's records task to CHANGELOG-append-only with an explicit "one bullet, appended at the end of the Unreleased block" rule so the merge is a trivial conflict rather than a semantic one.

**6. Spec 236-241 (C1) — the route-factory arity bullet contradicts itself, and the design is unresolved.** "One shape, `(runtime, config = {})`" and "factories that need no runtime accept it optionally in the bag" are two different shapes. Evidence: `createAuthRoutes(config)`, `createEditorRoutes(config = {})`, `createPublicRoutes(config)` take no runtime today and have no runtime available at their call sites — `examples/showcase/src/chassis/public-routes.ts` exports a bare `PublicRoutesConfig` literal with no runtime import, and `createPublicRoutes` is consumed by three route files in both showcase and `templates/waymark`. Making runtime positional-first there forces a runtime import into every public route file of every consumer, for a parameter the factory ignores. This is the largest `Consumers must:` line on the list (the sweep says so at F16) and the spec leaves the implementer to pick. **Correction:** rule the shape in the spec before the plan is written, or drop F16 from the window. Recommended ruling: keep the arity split and record it as a convention (runtime-taking factories are `(runtime, config = {})`, runtime-free factories are `(config = {})`), amending `convention-parameter-bags` — which is cheaper than the break and costs nothing a developer feels twice.

**7. **9. ## Sizing verdicts

**Polish-A.** Over-scoped and under-ceilinged. Thirteen groups is already at the twelve-task line, but five of them (A3, A6, A8, A9, A11) carry five to seven independent findings each and one (A10) has an unstated ~317-comment sweep inside it, so the honest task count is 16-18 and the 6M ceiling — set against chassis-A's 4.4M for twelve tasks on a lighter gate — funds about twelve. Four items are unruled either/ors that the spec hands to the implementer (A5's contrast branch, A7's two SSR designs, A11's F2 re-export-or-amend, A10's split-if-large), each an escalation trigger of exactly the shape chassis-A hit. Cut A10's register sweep and A9's `cairnAccess` seam, move the reference-prose half of A11 to polish-B, split A6's design-system write and A8's seven findings, rule the four either/ors in the spec, and 6M for ~12 tasks becomes defensible.

**Polish-B.** Right-sized on paper, wrong on shape. Ten groups is comfortable and 4M is roughly chassis-A's per-task rate, but the pass is not docs-only as claimed: D11/D12 edit ten engine strings asserted by three test files and located in the two modules polish-A is simultaneously splitting, so B needs a full engine gate on that task and a hand re-authored hunk after rebase. Its largest item, the front door, depends on four untracked working-tree artifacts and an uncommitted `check:figures` gate that no worktree off `main` will see, and it is itself a pass-sized deliverable (an authored public page, two figures with alternatives, a file move, an arm-index change, two register reviews, and Geoff's read). Commit the substrate to `main` first, split the front door out, put `npm test` on the D11/D12 task, and give B sole ownership of the friction log and the reference pages.

**Polish-C.** The riskiest of the three and the most under-ceilinged. Eight groups understates it: the window is ~15-18 `Consumers must:` lines over ~35 renamed identifiers touching 365 files in-tree, its central item (F16 arity) is specified by two contradictory sentences with no runtime available at the `createPublicRoutes` call sites, and F18 changes discriminant *values*, not only names, which no consumer type error catches. 5M has to fund all of that plus a full release ritual, a from-scratch showcase e2e, and a scaffold proof against packed tarballs that chassis-A recorded failing on the first attempt. Rule the arity question in the spec, cut F20 and F18's value-grammar half (both of which the sweep itself offers as ruling-amendment alternatives, and F20 is its own lowest-ranked item), state the `Consumers must:` list length, and either accept the reduced pass at 5M or raise to 7M and keep the full window.
