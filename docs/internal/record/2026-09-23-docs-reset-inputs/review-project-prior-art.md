# Review: prior art from projects that drafted docs with agents

Reviewer scope: other projects' Claude (and comparable agent) docs work, 2025-2026. Anthropic guidance, docs-platform vendors, and the cases already in `research-*.md` (Petrenko, Vercel AGENTS.md evals, Mintlify, Stripe, Doc Detective) are excluded except where a new detail matters. **[Inference]** marks my own reasoning.

## Cases

1. **Contentful Optimization SDK, "a self-maintaining docs pipeline" (PR #369, merged 2026-07-13).** https://github.com/contentful/optimization/pull/369. This is the closest analogue to this spec. Source code flows to a knowledge base (KB) of verified facts, and the KB feeds the guides. Four Claude roles: `sdk-knowledge-author` (the only role that reads source), `guide-writer` (reads facts, not code), `guide-source-verifier` (checks claims against the KB and escalates unbacked claims), and `guide-newcomer-reviewer`. The dependency graph is machine-checked in both directions. Each fact carries a `file#Symbol` pointer, which a TypeScript-compiler validator resolves. Each KB file declares `feeds-guides`. What they found: line-range pointers rotted silently, so line numbers were dropped from the grammar. Some facts were circular, sourced to another doc; they were purged during migration. Guides that imitated sibling guides drifted, so they added per-archetype "recipes" and verbatim "fragments". Durable review findings are funneled back into the skill, recipe, or KB. Outcome on the Node guide: 41 claims verified, 2 newcomer blockers and 15 friction items fixed, and 6 rules funneled back. When `main` renamed an API family mid-branch, `knowledge:check` "pinpointed every source pointer the rename had invalidated." No token figures.
2. **Vercel Workflow SDK.** https://github.com/vercel/workflow/blob/main/.claude/agents/docs-writer.md and PR #3704 (https://github.com/vercel/workflow/pull/3704). One `docs-writer` agent with a checklist that names canonical pages to imitate. Completion is gated on `lint:links` and `pnpm test:docs`, which type-checks every code sample, using `// @setup` lines that are checked but hidden. #3704 was a single agent-driven style audit of 599 files. Its invariants were proven in code: 985 samples passed, heading slugs were preserved, and rendered links were checked.
3. **Nx `docs-reviewer`.** https://github.com/nrwl/nx/blob/master/.claude/agents/docs-reviewer.md. Pinned to Opus. It checks "coverage" (does a behavior change leave prose stale?) on every PR. Every report, including a clean one, must open with an `EVIDENCE_LINE`/`EVIDENCE_TEXT` pair from the diff, which the caller verifies. The stated reason: "I found no problems" and "I looked at no docs" produce identical text.
4. **MongoDB `docs-drift` skill** (2026-07-02). https://github.com/mongodb/docs/tree/master/.claude/skills/docs-drift. A script extracts the documented surface from the rendered AST, and a deterministic diff compares it with the source surface. Agents only triage the mismatches. A per-docset manifest is calibrated by humans on the first run.
5. **Microsoft Aspire on GitHub Agentic Workflows.** https://github.blog/ai-and-ml/github-copilot/automating-cross-repo-documentation-with-github-agentic-workflows/. Each merged product PR triggers a draft docs PR, and the review goes to the engineer who approved the feature. Over 30 days, 82 docs PRs had a 100% merge rate and a 44.8 h median to merge. Early on, 13% of drafts were false positives, fixed by adding negative examples.
6. **XRPL dev portal personas** (PR #3738, 2026-07). https://github.com/XRPLF/xrpl-dev-portal/pull/3738. Eight read-only persona reviewers. The author "built these from anonymized interviews" and declined to add a validator persona "without actual feedback."
7. **Pinecone `rings`** and **Contentful's newcomer reviewer**, both read-only persona judges with full-repo `Read/Grep/Glob`. **SaladCloud `tutorial-walkthrough-validator`** (https://github.com/SaladTechnologies/salad-cloud-docs/blob/main/.claude/agents/tutorial-walkthrough-validator.md) actually executes tutorials, with safe-execution tiers: GET runs live, and a mutating call runs only if reversible and credentialed, else it is dry-run-checked against the OpenAPI spec.
8. **Neon.** A supervisor, planner, drafter, and refiner loop with a 3-iteration cap, a "trivial tier" bypass, and a per-content-type gold corpus. It explicitly forbids a local build ("the final validation should act as an intelligent linter"). https://github.com/neondatabase/website/tree/main/.claude/agents. Their Devin trial reported that multi-file agent edits needed "20+ manual commits" of polish. https://neon.com/blog/ai-workflows-for-docs-devin (2025-06).
9. **Ferri-Benedetti (passo.uno).** He runs deterministic tools first (Vale, Codespell, Lychee) and pipes their output to an LLM to filter (https://passo.uno/agentic-workflows-for-docs/). In his Sonnet experiments, "For agents" section labels had no effect, while an explicit recommendation raised selection of the intended procedure from 33% to 100% (https://passo.uno/if-you-are-an-agent-read-this/). A 2025 post lists fabrication and "no strategic vision" as the core failures (https://passo.uno/whats-wrong-ai-generated-docs/).
10. **eneo-ai issue #781** (closed 2026-09-05). https://github.com/eneo-ai/eneo/issues/781. An audit of 30 pages found invented endpoints, invented env vars, and 20 pages with errors. The fix: rewrite from code, check links in CI, and run an independent re-verification against code.

Cross-case pattern: every durable setup is deterministic where it can be and agentic only for judgment. No project besides Petrenko and Salad tests docs with a reader that *acts*; the common practice is persona judges, which this spec's research already rejects. No project published token accounting for its review chain.

## Findings

### Critical

**C1. The facts container would launder old-page prose back into the reset.** Contentful purged "circular" facts, meaning facts whose evidence was another doc, because they carry doc text forward as if verified (#369). Here, `docs/internal/facts/` holds about 182 `[candidate: sourced to the page only]` bullets against about 590 `[verified]` (extend alone has 100). Ruling 1 says only verified facts survive and drafters never open old pages. Yet the page chain will cite container IDs, and a candidate ID is old-page prose by another route. **Proposed change:** in pass 1 component 5, the ID migration also sorts every candidate. Each one is traced to code (becoming `[verified]`), tagged `[rejected]`, or excluded from drafter source packs. The runner then fails any drafted claim that cites a candidate ID. Add this to pass 1's exit gate.

**C2. Stripping claim IDs at the gate throws away the only proven drift mechanism.** Contentful survived an upstream API-family rename because the graph ran both ways: source to fact (checked pointers) and fact to guide (`feeds-guides`). Component 3 creates exactly that fact-to-page map and then deletes it. The spec names no post-reset drift mechanism beyond pass discipline. **Proposed change:** keep each page's claim-to-ID map as a committed sidecar (or as stripped-at-render comments), not stripped at the gate. Add a `check:facts` mode that lists every page citing a changed or retagged bullet. The `cairn-pass` close then recomposes those pages. Record this under "What changes downstream."

### Major

**M1. Line-number source pointers rot; anchor on symbols.** Contentful dropped line ranges after finding stale `:148-209` pointers. They switched to `file#Symbol`, verified by the compiler, so a rename fails the build. `check-facts.mjs` resolves `path:line` with a ±10-line window and token matching, which it calls "a weaker proof." The ID migration touches every bullet anyway. **Proposed change:** add symbol-anchored `Source:` pointers to the pass 1 ID syntax. Use a TS-compiler resolver for `src/`, and `go/packages` or a grep-for-declaration resolver for `tool/`. Keep line pointers only for non-code files.

**M2. A structural ceiling makes silent empty reads likely, so require read evidence.** Nx found that a clean verdict and a no-op verdict are textually identical. It demands a verifiable quoted line with its line number. Petrenko's agents "failed silently" under rate limits. **[Inference]** A misprepared docs-only directory yields a reader reporting "no stalls," and planted-defect validation catches this once, at pass 1, not per run. **Proposed change:** the reader's fixed shape opens with pages opened, plus one quoted line with its path:line from each page the job touched. The runner verifies these and records an unverifiable report as *failed*, never clean.

**M3. There is no funnel-back from reader findings into the drafter's inputs.** Contentful and XRPL route each durable finding to its layer. Contentful's first run funneled 6 reader rules into the authoring checklist. The spec checks only that each redraft applied its findings. A stall that recurs across pages never reaches the profile skill or the exemplars, and the calibration trial's pages "never merge," so their lessons have no destination. **Proposed change:** add a `rule-candidate` field to the reader and editor report shapes. Add a pass 2 step after the trial that folds rule candidates into the profile files, the page-type registry, or the facts container. Give each chain pass's close the same fold.

**M4. Make coverage deterministic where the surface is declared in code.** MongoDB diffs the extracted docs surface against the source surface by script, and uses agents only for triage. cairn's CLI tree (cobra), its exports, its log events, and `conditions.ts` anchors are all enumerable. **Proposed change:** pass 2 step 4 seeds the jobs ledger from a script that enumerates those surfaces. The outline review's "coverage against the code" lens then reads only the unmatched residue, not the code.

**M5. The chain's stages must earn their place, the same way tracks do.** The durable cases run lean. Aspire used one drafter and an SME for a 100% merge rate. Contentful used four single-purpose roles and one validator, and Vercel one writer plus deterministic gates. Neon's five-agent loop has not changed since January (**[Inference]** a weak signal of disuse), and its own trial needed 20+ manual polish commits. Pass A cost about 900K tokens a page. **Proposed change:** add a third arm to the calibration trial: drafter, deterministic checks, and one reader, with no register editor and no fact read. Adopt the full chain only for the stages whose catches that arm misses. Fix the decision rule now, as was done for O and P.

### Minor

**m1. Ground profiles in real people.** XRPL refused a persona that no interview supported. **Proposed change:** each profile cites its evidence (named club editors, Geoff as operator, the club sites' designers). The site designer profile is marked provisional, and its trial result is read as provisional.

**m2. State one recommended path.** The explicit-recommendation effect (33% to 100%), with no effect from agent labels, supports ruling 4. **Proposed change:** the page contract's Job field requires the one recommended path, stated explicitly, wherever alternatives exist.

**m3. Pipe deterministic findings into the register editor.** Following Ferri-Benedetti, the register editor receives Vale and `tellgrader` output as input and filters it, rather than rediscovering mechanical tells.

**m4. Reader credentials.** For the open question on how the `cairn`-binary reader authenticates, borrow Salad's tiers. Read-only commands run against a fixture site. A mutating command is dry-run-validated against the cobra tree and the `--json` help.

**m5. Pinned anchors.** Vercel #3704 proved "no changed heading slugs" in code. The pinned-anchor inventory should become a gate, not a list.
