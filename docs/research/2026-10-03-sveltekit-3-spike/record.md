## `cloudflare:workers` facts proved (for `durable-gotchas.md`, Task 13)

1. A `cloudflare:workers` import inside a packed engine and a packed dev package resolves under `vite dev`,
   `vite build`, and `wrangler dev` with no `ssr.noExternal`, no `file:`, and no `npm link` in the project.
2. `env.X` returns the `wrangler.jsonc` `vars` value under `vite dev` (adapter proxy) and `wrangler dev`.
3. Any `env` read or `withEnv` call while prerendering fails the build with
   `Cannot access cloudflare:workers in a prerenderable route` (quoted control run, exit 1). A `building` gate
   from `$app/env` avoids it. `$app/environment` is Kit 2's name; Kit 3 names it `$app/env`.
4. `await import('$app/env')` in `try`/`catch` resolves in a real Kit 3 build (the gate fires) and is the form
   a plain esbuild pass tolerates; a static `import { building } from '$app/env'` in a barrel-reachable module
   fails the boundary test (`Could not resolve "$app/env"`).
5. Wrangler's plain esbuild treats `cloudflare:*` as external (`cloudflare-internal-imports`), so the boundary
   test's external list needs `cloudflare:*` or the engine's own `cloudflare:workers` import fails it.
6. `withEnv({ ...env, X }, () => resolve(event))` in a handle makes `X` visible to engine code and site code
   alike, across multiple awaits, inside a `ReadableStream` `pull`, and in a promise a `load` returns, under
   both `vite dev` and `wrangler dev`.
7. Adapter 8 passes no `platform`: a Kit 2-era engine under it answers `/admin/login` with a 500
   (`guard.refused`, `config.bindings-missing`).
8. `wrangler dev <output>/_worker.js --port N` serves adapter 8 output, assets included. The `sv` adapter-cloudflare
   scaffold's `preview` script is exactly that, and its `build` script runs `wrangler types --check` first, so a
   project needs `npm run gen` before `npm run build`.
9. On Kit 2.70 / adapter 7 under `wrangler dev`, `--var CAIRN_DEV_BACKEND:1` populates both
   `platform.env.CAIRN_DEV_BACKEND` and `process.env.CAIRN_DEV_BACKEND` (the showcase's `devBackendOptIn` read);
   without it the dev backend stays off.

Scaffold notes for Task 12: `sv` 1.1.0 replaces `$lib` with `#lib` subpath imports (`package.json` `imports`),
so a harness or template wiring uses relative paths or `#lib/*`; a client component importing a
`src/lib/server/**` module fails the build with `server_only_import`, so the adapter config (read by the admin
page component) lives outside `lib/server`.
