# Public preview for a non-editor (Phase F, pass two) — implementation plan

> **For agentic workers:** execute task-by-task per the repo's standing method: dispatch each task
> to `cairn-implementer` (pinned Sonnet), test-first; the main loop reviews each diff and confirms
> the full gate before the next dispatch. The spec is
> [`../specs/2026-08-06-history-revert-preview-design.md`](../specs/2026-08-06-history-revert-preview-design.md)
> (part 3); read it before task 0. **Task 0 blocks every dispatch: preview is a permanent public
> surface, and the standing rule puts the adversarial review BEFORE the first implementer
> dispatch, not at pass end.**

**Goal:** an editor hands a draft to someone who is not an editor: an opaque D1-backed token
mints from the edit screen, and a site-mounted never-prerendered page renders the draft through
the site's own entry-rendering path.

**Architecture:** a new `preview_tokens` table in `AUTH_DB` (bundled migration, opt-in);
`mintPreviewToken` inserts, `previewLoad` verifies by lookup (row valid, unexpired, pending
branch still exists) and returns the public page's own data shape plus preview metadata. A
preview link dies with its branch: publish and discard already delete it, so revocation is
structural. No cookie, no session, read on one draft entry only.

## Global constraints

- Reserved names land exactly as reserved (C2 R11): `mintPreviewToken`, `PreviewTokenConfig`,
  `preview.token.minted`, `preview.rejected` (snake_case `reason`). The spec un-reserves
  `createPreviewRoute`; the load is `previewLoad` under R1's `Load` grammar. The mint action's
  member and facade key derive under R1 in task 2 and are proposed there as `previewMintAction`
  / `previewMint`; the task confirms them against `docs/internal/api-surface.md` before landing.
- Additive only; the migration is opt-in with the audit-sink discipline (the guide states what
  the table needs, not only the file name, per the ASC migration's correction).
- Per-task gate: targeted tests, `npm run check` 0/0, `npm test` exit 0. TSDoc, no em dash,
  every export documented. Feature worktree off `main`; mind the showcase-symlink gotcha.
- Token plaintext is never stored or logged: the row holds the hash (`hashToken`,
  `src/lib/auth/crypto.ts`), and `preview.token.minted` carries concept, id, editor, and expiry,
  never the token.

### Task 0: the adversarial review gate (no code)

**Dispatch, in parallel, before any implementation:** `web-auth-security-reviewer` (mandatory
lens: token entropy and comparison, enumeration and timing, expiry enforcement, what a leaked
URL grants, log hygiene) and `svelte-reviewer` (lens: the load's data-shape reuse, prerender
exclusion, what the preview page can leak through SvelteKit's serialized data). Both read the
spec's part 3 and this plan, not code.

**Outcome:** findings triaged into this plan as constraint amendments before task 1 dispatches.
A finding that moves a design decision goes back to Geoff in one batched question; anything
else lands as a constraint edit. Record the round in the plan's post-mortem section at pass
end.

### Task 1: the token store and migration

**Files:**
- Create: `migrations/0003_preview.sql` (`preview_tokens`: token hash, concept, entry id,
  issuing editor, expiry, created-at; the exact DDL is the implementer's, matching the existing
  migrations' conventions in `0000_auth.sql`)
- Create: `src/lib/auth/preview-store.ts` (mint-insert, lookup-by-hash, expiry check; the D1
  access idiom copies `src/lib/auth/store.ts`)
- Test: unit spec beside the auth-store specs, on the vitest workerd project (real D1 via the
  migrations loader in `vitest.config.ts`)

**Interfaces:**
- Consumes: `generateToken`, `hashToken` (`src/lib/auth/crypto.ts`), `AUTH_DB`.
- Produces: `insertPreviewToken(db, record): Promise<void>` and
  `findPreviewToken(db, tokenHash): Promise<PreviewTokenRow | null>` (internal, not exported
  from any subpath); `PreviewTokenRow { concept: string; entryId: string; editor: string;
  expiresAt: string }`.

**Outcome:** the storage half, opaque-row discipline, hash-only at rest.

**Acceptance criteria:** tests prove insert-then-find round trip, the miss on an unknown hash,
expiry exclusion at the boundary, and that the stored value is the hash (a find by the
plaintext misses).

### Task 2: `mintPreviewToken` and the edit-screen action

**Files:**
- Create: `src/lib/sveltekit/preview.ts` (`mintPreviewToken`, `PreviewTokenConfig`)
- Modify: `src/lib/sveltekit/content-routes-core.ts` (the `previewMintAction` member),
  `src/lib/sveltekit/cairn-admin.ts` (facade key `previewMint`, gated to the `edit` view),
  `src/lib/sveltekit/types.ts` + barrel
- Modify: `src/lib/components/CairnAdmin.svelte`'s edit screen (the share affordance surfacing
  the minted URL; admin design system applies)
- Test: integration specs beside the content-routes specs; component spec for the affordance

**Interfaces:**
- Consumes: task 1's store; `pendingBranch`/`branchHead` (the mint refuses when no draft
  exists: a preview shares a draft, and without a pending branch there is nothing to share).
- Produces: `mintPreviewToken(db, config, record): Promise<{ token: string; expiresAt: string }>`
  exported from `/sveltekit`; `PreviewTokenConfig { ttlMs?: number }` defaulting to 7 days;
  the facade action returning the preview path (`/preview/<token>` by convention, the site's
  mount point documented rather than enforced); log `preview.token.minted`.

**Outcome:** an editor on the edit screen mints and copies a link in one action; minting with
no open draft refuses on the page.

**Acceptance criteria:** tests prove the default and configured TTLs, the no-draft refusal,
the log record's fields (and the token's absence from it), and that two mints yield two
independent valid rows (multi-reviewer sharing).

### Task 3: `previewLoad`

**Files:**
- Modify: `src/lib/sveltekit/preview.ts` (the load), `src/lib/sveltekit/index.ts` (export)
- Test: integration spec against the fake backend and real D1 (workerd project)

**Interfaces:**
- Consumes: task 1's store; `pendingBranch`, `branchHead`, `readFile` off the branch; the same
  composition the public load runs (`composeRuntime`'s delivery arm, exactly the modules the
  site's public entry load consumes — the implementer traces the public load's call path and
  reuses it, adding nothing preview-specific to the composition itself).
- Produces: `previewLoad(runtime, event): Promise<PreviewData>` where `PreviewData` is the
  public entry page's data shape intersected with
  `{ preview: { expiresAt: string; published: { permalink: string } | null } }`; every refusal
  throws SvelteKit `error(404)` after logging `preview.rejected` with `reason:
  'unknown' | 'expired' | 'branch_gone'`.

**Outcome:** the verification chain (row, expiry, branch) and the two success shapes: the
draft rendered, or the published-courtesy shape (`published` set, entries fields from `main`)
when the token is valid but the branch is gone because the entry published.

**Constraints:** all three refusals answer identically from outside (404, no
which-check-failed distinction in the response; the distinction lives in the log only). No
cookie is read or set. The load never touches `locals`.

**Acceptance criteria:** tests prove the draft render path returns the public shape, each
refusal's log reason, the identical outward 404s, the courtesy path against a published entry,
and expiry at the boundary.

### Task 4: the banner component and docs shape

**Files:**
- Create: `src/lib/components/PreviewBanner.svelte`, exported from `/components`
- Test: component spec

**Interfaces:**
- Consumes: `PreviewData['preview']` (task 3).
- Produces: the default draft-banner treatment (visible "Draft preview · expires <date>", the
  published-courtesy variant linking the live permalink); a site may ignore it and render its
  own from the same metadata.

**Acceptance criteria:** component tests for both variants; the banner is presentational only
(no fetch, no state).

### Task 5: showcase wiring and e2e

**Files:**
- Create: `examples/showcase/src/routes/preview/[token]/+page.server.ts` (wires `previewLoad`;
  `export const prerender = false`) and `+page.svelte` (reuses the showcase entry page's
  rendering, `PreviewBanner` on top; the fixture entry includes a registered content component
  so the fidelity claim is proven, not asserted)
- Modify: `examples/showcase/e2e/` (a new `preview.spec.ts`)
- Test: the e2e suite

**Outcome:** the reference wiring every consumer copies, and the end-to-end proof: mint from a
signed-in edit screen, fetch the URL with no session, see the draft with its component
rendered; the three rejections 404; publish the draft, refetch, land on the courtesy page.

**Acceptance criteria:** the spec passes on CI's real checkout (the worktree symlink gotcha
makes a local-only green insufficient); the spec asserts the component's rendered output, not
just the entry body; `preview.rejected` reasons assert via the dev backend's log capture if
available, else via response status only.
