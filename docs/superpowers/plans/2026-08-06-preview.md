# Public preview for a non-editor (Phase F, pass two) — implementation plan

> **For agentic workers:** execute task-by-task per the repo's standing method: dispatch each task
> to `cairn-implementer` (pinned Sonnet), test-first; the main loop reviews each diff and confirms
> the full gate before the next dispatch. The spec is
> [`../specs/2026-08-06-history-revert-preview-design.md`](../specs/2026-08-06-history-revert-preview-design.md)
> (part 3); read it before task 0. **Task 0 blocks every dispatch: preview is a permanent public
> surface, and the standing rule puts the adversarial review BEFORE the first implementer
> dispatch, not at pass end.**

**Goal:** an editor hands a draft to someone who is not an editor: an opaque D1-backed token
mints from the edit screen, and a site-mounted never-prerendered page renders the draft through
the site's own entry-rendering path.

**Architecture:** a new `preview_tokens` table in `AUTH_DB` (bundled migration, opt-in);
`mintPreviewToken` inserts, `previewLoad` verifies by lookup (row valid, unexpired, pending
branch still exists) and returns the public page's own data shape plus preview metadata. A
preview link dies with its branch: publish and discard already delete it, so revocation is
structural. No cookie, no session, read on one draft entry only.

## Global constraints

- Reserved names land exactly as reserved (C2 R11): `mintPreviewToken`, `PreviewTokenConfig`,
  `preview.token.minted`, `preview.rejected` (snake_case `reason`). The spec un-reserves
  `createPreviewRoute`; the load is `previewLoad` under R1's `Load` grammar. The mint and
  revoke actions' members and facade keys derive under R1 in task 2, proposed as
  `previewMintAction`/`previewMint` and `previewRevokeAction`/`previewRevoke`; the task
  confirms them against `docs/internal/api-surface.md` before landing, and
  `preview.token.revoked` joins the R6 log vocabulary.
- Additive only; the migration is opt-in with the audit-sink discipline (the guide states what
  the table needs, not only the file name, per the ASC migration's correction).
- Per-task gate: targeted tests, `npm run check` 0/0, `npm test` exit 0. TSDoc, no em dash,
  every export documented. Feature worktree off `main`; mind the showcase-symlink gotcha.
- Token plaintext is never stored, logged, or echoed into an error message, on ANY event: the
  row holds the hash (`hashToken`, `src/lib/auth/crypto.ts`); `preview.token.minted` AND
  `preview.rejected` carry concept, id, editor, expiry, or reason, never the token or any
  attacker-supplied token string. If a correlator is wanted, the first 8 hex characters of the
  hash, nothing longer. (The engine already scrubs a seam's thrown error for `token=`;
  `auth-routes.ts` is the precedent.)
- Do NOT introduce a constant-time compare on the lookup path (adversarial round): the attacker
  controls the plaintext, not the hash, and steering SHA-256 output against a B-tree comparison
  requires a partial preimage. `tokensMatch` stays out of this feature; say so in a comment so
  a later reviewer doesn't add it as cargo cult.
- The bundle decision is made (Geoff, 2026-08-06): the site passes its real `PublicRoutesConfig`
  and the globbed corpus rides into the Worker bundle for v1. Task 5 carries the size assertion;
  the narrowed manifest-backed resolver is a ROADMAP item, not this pass's work.

### Task 1: the token store and migration

**Files:**
- Create: `migrations/0003_preview.sql` (`preview_tokens`; the DDL is the implementer's within
  three fixed points from the adversarial round: `token_hash TEXT PRIMARY KEY` matching
  `magic_token`'s idiom, an index on `expires_at` for the sweep, and an index on
  `(concept, entry_id)` for the revoke/cleanup deletes — indexes are free now and a second
  migration against every adopter later)
- Create: `src/lib/auth/preview-store.ts` (mint-insert, lookup-by-hash, expiry check, and the
  delete-by-entry used by revoke and by rename/delete/discard cleanup; the D1 access idiom
  copies `src/lib/auth/store.ts`)
- Test: unit spec beside the auth-store specs, on the vitest workerd project (real D1 via the
  migrations loader in `vitest.config.ts`)

**Interfaces:**
- Consumes: `generateToken`, `hashToken` (`src/lib/auth/crypto.ts`), `AUTH_DB`.
- Produces: `insertPreviewToken(db, record): Promise<void>` (which batches
  `DELETE ... WHERE expires_at <= ?` with its insert, the same no-cron sweep `issueToken` and
  `createSession` already run), `findPreviewToken(db, tokenHash): Promise<PreviewTokenRow |
  null>`, and `deletePreviewTokens(db, concept, entryId): Promise<number>` (all internal, not
  exported from any subpath); `PreviewTokenRow { concept: string; entryId: string; editor:
  string; expiresAt: string }`.

**Outcome:** the storage half, opaque-row discipline, hash-only at rest, self-sweeping like its
two sibling token tables.

**Acceptance criteria:** tests prove insert-then-find round trip, the miss on an unknown hash,
expiry exclusion at the boundary, the stored value being the hash (a find by the plaintext
misses), the insert-time sweep clearing expired rows, and delete-by-entry returning its count.

### Task 2: `mintPreviewToken`, the mint and revoke actions, and the lifecycle cleanup

**Files:**
- Create: `src/lib/sveltekit/preview.ts` (`mintPreviewToken`, `PreviewTokenConfig`)
- Modify: `src/lib/sveltekit/content-routes-core.ts` (the `previewMintAction` and
  `previewRevokeAction` members, AND the row-cleanup lines in `renameAction`, `deleteAction`,
  and `discardAction`), `src/lib/sveltekit/cairn-admin.ts` (facade keys `previewMint` and
  `previewRevoke`, gated to the `edit` view), `src/lib/sveltekit/types.ts` + barrel
- Modify: `src/lib/components/CairnAdmin.svelte`'s edit screen (the share affordance surfacing
  the minted URL and the revoke-all affordance beside it; admin design system applies)
- Test: integration specs beside the content-routes specs; component spec for the affordances

**Interfaces:**
- Consumes: task 1's store including `deletePreviewTokens`; `pendingBranch`/`branchHead` (the
  mint refuses when no draft exists: a preview shares a draft, and without a pending branch
  there is nothing to share); `requireEntryFromParams`; `requireOrigin(env)`.
- Produces: `mintPreviewToken(db, config, record): Promise<{ token: string; expiresAt: string }>`
  exported from `/sveltekit`; `PreviewTokenConfig { ttlMs?: number }` defaulting to 7 days,
  validated at construction in the `defineRoles` idiom (finite, positive, one minute to 30
  days, actionable `PreviewTokenConfig:`-prefixed error); the mint action returning the preview
  URL (absolute form derived from `requireOrigin(env)`, NEVER `event.url.origin`, which is
  host-header-controlled on Cloudflare); the revoke action deleting every row for the entry;
  logs `preview.token.minted` and `preview.token.revoked` (with the count).

**Outcome:** an editor on the edit screen mints and copies a link in one action and can kill
every outstanding link in one more; minting with no open draft refuses on the page; rename,
delete, and discard clear the entry's rows (dead anyway, and clearing closes an id-reuse
collision where a stale token could resolve to a different entry's later draft). **Publish
does NOT clear rows** — the ended page requires the row to outlive the branch, a stated
coupling, not an oversight.

**Constraints (the round's one High lands here):** both actions call
`requireEntryFromParams(runtime, event)` as their FIRST statement, exactly as `saveAction` and
`publishAction` do. The view gate is a path parse, not authorization: without this call, a
signed-in `none`-capability session (a designed-for population, and one that config drift
manufactures by accident) mints a working preview of any draft, a clean read bypass of the
engine's own content authorization.

**Acceptance criteria:** tests prove the default and configured TTLs plus the config
validation, the no-draft refusal, the log records' fields (and the token's absence from every
one of them), two mints yielding two independent valid rows (multi-reviewer sharing), the
revoke deleting both, the rename/delete/discard cleanup, publish leaving rows intact, AND the
two authorization refusals: a `none`-capability session gets the same refusal `saveAction`
gives it, and an access-map-denied editor likewise. **Task-sizing note:** this task now
carries roughly five deliverables (mint, revoke, cleanup, UI, authorization); if it strains a
single dispatch, the split point is UI-affordances-versus-server-actions, and the orchestrator
should say so rather than absorb it.

### Task 3: `previewLoad`

**Files:**
- Modify: `src/lib/sveltekit/preview.ts` (the load), `src/lib/sveltekit/index.ts` (export)
- Test: integration spec against the fake backend and real D1 (workerd project)

**Interfaces:**
- Consumes: task 1's store; `readFile` off the branch (NO separate `branchHead` pre-check: the
  read itself is the existence test, so the check-then-read race collapses into one call and a
  not-found read IS the branch-gone path); the marking link and fragment resolvers built from
  the pending branch's manifest (the pair the admin edit preview uses), never the build's
  throwing pair; a media resolver built from `media.json` read off the backend at request time
  (branch first, `main` fallback); and the site's own `PublicRoutesConfig`, passed by the site
  as the literal object it hands `createPublicRoutes`.
- Produces: `previewLoad(runtime, config, event): Promise<PreviewData>` where
  `type PreviewData = EntryData & { preview: { state: 'draft' | 'published'; expiresAt: string;
  published: { permalink: string } | null } }`, with a compile-time assertion in the suite that
  `PreviewData` adds no key beyond `preview` (so a future `EntryData` field breaks this build,
  not a consumer's); every refusal throws SvelteKit `error(404)` after logging
  `preview.rejected` with `reason: 'unknown' | 'expired' | 'branch_gone'`.

**Outcome:** the verification chain in strict order — token SHAPE first
(`^[A-Za-z0-9_-]{43}$`, the exact form `generateToken` emits; a malformed token is a 404 with
NO D1 read and NO log, killing spray traffic at zero cost), then row, then expiry, then the
branch read — and the two success shapes: the draft rendered (`state: 'draft'`), or the ended
page (`state: 'published'`, `published` set when the entry's file exists on the default
branch) for a valid unexpired token whose branch is gone. Expiry strictly precedes the branch
read, so an expired token never becomes a perpetual has-it-published-yet probe.

**Constraints:** all three refusals answer identically in status and body (the distinction
lives in the log only); response TIMING differs by class since the fast paths precede any
network call, and that is accepted — do not add artificial delay. No cookie is read or set;
the load never touches `locals`. Every response, refusals and courtesy included, carries the
headers (`x-robots-tag: noindex, nofollow`, `cache-control: private, no-store`,
`referrer-policy: no-referrer`, `x-content-type-options: nosniff`, frame denial) via
`event.setHeaders` — `/preview` is not an admin path, so the guard's header layer never
touches it. A missing `AUTH_DB` binding answers a drained 503 with a binding-named log,
following `media-route.ts`'s precedent exactly (a half-configured adopter is the LIKELY
first-run state). `previewLoad` throws a descriptive error when `building` (from
`$app/environment`) is true, so a site that lets the route prerender gets a red build naming
the fix instead of a token-bearing static asset.

**Acceptance criteria:** tests prove the draft render path returns the public shape with the
marking resolver behavior (a draft linking an unpublished sibling renders 200 with the link
marked, never 500), the media path resolving an upload newer than the site build, each
refusal's log reason, the identical outward 404s including the no-read malformed-shape path,
the ended page against a published entry, an EXPIRED token against a published entry answering
404 rather than the ended page, the header set on every path, the 503 on a missing binding,
and the build-time throw.

## Execution amendments (task 0 round, 2026-08-06, code at `11a5f8a1`)

The pre-dispatch round (web-auth-security + SvelteKit data-shape lenses, both Opus) confirmed
the folded round-2 mitigations against the real code and corrected the drift below. These
amendments BIND every dispatch; where they conflict with the task text above, the amendment
wins. The spec's "Round 3 corrections" block carries the same content at design altitude.

**Task 1 (token store):**
- `expires_at INTEGER NOT NULL`, epoch milliseconds, matching `magic_token`/`session`;
  `PreviewTokenRow.expiresAt: number` through the store and `mintPreviewToken`. A display
  string appears only at the `PreviewData.preview.expiresAt` boundary (task 3). Rationale:
  SQLite compares across type classes by class, so TEXT `expires_at` against a numeric bind
  never sweeps and never expires.
- The expiry-boundary test must insert one row via a raw `db.prepare(...).bind(<number>)`,
  not only through `insertPreviewToken`, so a column-type mismatch is observable.
- The insert-time sweep fires only on mint (rare, long TTLs), so expired rows linger longer
  than the sibling tables'; say so in a comment rather than implying parity. Expiry is
  enforced at lookup, so this is cosmetic.

**Task 2 splits into 2a (server) and 2b (UI), the plan's own named split point.**
- **2a:** `mintPreviewToken` + `PreviewTokenConfig`, both actions, lifecycle cleanup, logs.
  Amendments: the row cleanup goes INSIDE `deleteEntry` covering both success exits (the
  branch-only delete and the post-commit path), never in the `deleteAction` wrapper, so
  `listDeleteAction` cannot bypass it; add a test that the LIST delete clears rows.
  `deleteEditor` and `removeOwnerIfNotLast` batches gain
  `DELETE FROM preview_tokens WHERE editor = ?` (the third credential class joins the
  existing cascade), with tests. The mint action's response sets `cache-control: no-store`
  (the one admin payload carrying a bearer credential). A missing `preview_tokens` table at
  mint answers an actionable `ActionFailure` naming `migrations/0003_preview.sql`. The three
  `preview.*` events join the `CairnLogEvent` union in `src/lib/log/events.ts`. Never build
  the absolute preview URL into any value that can reach an error message.
- **2b:** the edit-screen share + revoke affordances (admin design system applies), component
  spec. The revoke UI may show count and expiry but must never imply a minted URL is
  recoverable (hash-only at rest; the plaintext exists once, in the mint response).

**Task 3 splits into 3a (extractions) and 3b (`previewLoad`).**
- **3a, additive refactors with their own tests, no behavior change:**
  (1) extract the per-entry composition from `src/lib/delivery/public-routes.ts` into an
  exported `composeEntryData(config, entry, overrides?)` where `overrides` substitutes the
  link, fragment, and media resolvers and the hero derivation consumes the substituted media
  resolver; `entryLoad` becomes lookup-then-compose with byte-identical output (existing
  suite proves it). (2) extract `manifestFragmentResolver(targets)` beside
  `manifestLinkResolver` in `src/lib/content/manifest.ts`; repoint
  `EditPage.svelte`'s inline `$derived.by` fragment resolver at it.
- **3b, the load itself, consuming 3a:**
  - Manifest: read from the DEFAULT branch and upsert the draft's re-derived row in memory
    (`manifestEntryFromFile` + `upsertEntry`, the save-time link-guard pair). There is no
    pending-branch manifest. Apply the admin's non-routable-concept filter to link targets;
    do not set `previewTitle`.
  - Media: `buildMediaResolver` with `runtime.resolvedAssets` over `media.json` read branch
    first, `main` fallback. Never `manifestMediaResolver` (hardcoded url form breaks
    twin-render equivalence on any site using `publicBase`, presets, or `imageDetail`).
  - Descriptor from `runtime.concepts`; re-validate the row's stored values
    (`findConcept` + `isValidId`) before building any path; a miss answers the uniform 404,
    reason `row_invalid`.
  - A draft whose entry fails descriptor validation (`byId` → `undefined`; revert-as-draft
    can produce this legitimately) answers the uniform 404, reason `draft_invalid`, never
    `branch_gone`.
  - A thrown `no such table` around the store lookup answers the uniform 404, reason
    `table_missing`, never a raw 500 and never D1's error text.
  - Reason vocabulary is therefore `unknown | expired | branch_gone | row_invalid |
    draft_invalid | table_missing`; all six join `docs/reference/log-events.md` in task 6.
  - Headers: ONE `event.setHeaders` call as the first statement, before any await:
    `x-robots-tag: noindex, nofollow`, `cache-control: private, no-store`,
    `referrer-policy: no-referrer`, `x-content-type-options: nosniff`,
    `x-frame-options: DENY` (not CSP `frame-ancestors`, which would collide with a site's
    kit-generated CSP header). SvelteKit applies `setHeaders` to the error response a thrown
    `error()` renders, confirmed against the installed kit.
  - All refusals throw `error(404, NOT_FOUND_MESSAGE)` with ONE shared literal constant whose
    wording is a plain not-found that never names preview (the reason lives in the log only).
  - Missing `AUTH_DB` binding: `error(503)` after the binding-named log (the media-route
    precedent's log and status; a load cannot return a bare Response).
  - `locals`: never reads `cairnEditor`/`cairnAccess`, sets no cookie; the backend resolves
    through the standard `locals.cairnBackend ?? runtime.backend.connect(env)` seam (state
    the reasoning in a comment).
  - `$app/environment` (`building`) is the first `$app` import outside `src/lib/components`;

**Task 6 (docs) additions, each a round finding:**

- A role or access-map change does not retro-revoke already-minted links; editor REMOVAL

- The layout chain above the preview route must not `setHeaders` any of the five names the
  load sets (SvelteKit throws a 500 on a duplicate).
- An origin Cache Rule overriding cache eligibility on `/preview/*` would serve one holder's

- The ended page is a bounded publish oracle for the rest of the TTL (deliberate; one line so

- The disambiguation note covers BOTH existing `preview` keys: `CairnRuntime.preview` (editor

- ROADMAP files one more entry beyond the two planned: an engine-level rate-limit seam for
